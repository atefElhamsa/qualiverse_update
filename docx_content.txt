Frontend System Design and Implementation
Comprehensive System Architecture, Flow, and Module Breakdown
1. Introduction
The frontend ecosystem of the QualiVerse platform is meticulously engineered to provide an accessible, robust, and highly responsive interface tailored for the academic staff and administration of the Faculty of Computers and Information at Tanta University. Operating as the primary interface between complex academic workflows and the end-users, the frontend relies heavily on the Flutter framework. This chapter details the architectural patterns, the state management flows, and the comprehensive breakdowns of every single module in the system without relying on raw code implementations.
2. Application Architecture and State Management
The application is structured using a strict Clean Architecture pattern divided into Presentation, Domain, and Data layers. This ensures that the user interface is completely decoupled from the ASP.NET backend. State is managed entirely via the BLoC (Business Logic Component) pattern. Every screen is backed by a specific Cubit that dictates its state (Loading, Success, Error) and handles all data fetching asynchronously. This strict adherence to unidirectional data flow eliminates spaghetti code and ensures deterministic UI rendering.
3. CI/CD and DevOps Pipeline
To ensure zero-downtime updates, the platform integrates a Continuous Integration pipeline via GitHub Actions. Upon pushing code to the repository, a cloud virtual machine automatically provisions a Windows environment, compiles the Flutter codebase into a native executable, and uses Inno Setup to generate a professional installation wizard (Setup.exe). The pipeline then automatically pushes this update to a secure cloud server, where existing desktop clients poll a version.json file to automatically download and install updates in the background, entirely removing the need for manual distribution.

Future<void> fetchNotifications() async {
  try {
    emit(NotificationLoading());
    final response = await dio.get(EndPoints.getNotifications);
    final notifications = (response.data as List).map((n) => NotificationModel.fromJson(n)).toList();
    emit(NotificationSuccess(notifications));
  } catch (e) {
    emit(NotificationError(e.toString()));
  }
}

This code fetches real-time alerts from the backend. The Cubit emits a Loading state to show a spinner, then makes an authenticated GET request. If successful, it parses the JSON into Dart models and updates the UI.

When a user interacts with the Notification Management System, the corresponding BLoC immediately transitions into a Loading state. This prevents duplicate user inputs. The Data Layer formulates a secure HTTP request, appending the user's JWT token via the global Dio interceptor. Once the ASP.NET backend processes the request and responds, the raw JSON payload is parsed into strongly-typed Dart domain entities. The BLoC then emits a Success state, triggering a reactive UI rebuild.

Future<void> _pollGenerationStatus() async {
  bool isFinished = false;
  while (!isFinished) {

To highlight the advanced technical capabilities of the QualiVerse frontend, we examine the core engine driving the AI Course Description Wizard. This feature is heavily reliant on the AiDescriptionCubit, which manages a highly complex, multi-stage state machine involving massive data structures and asynchronous long-polling.



Architectural Significance of the Above Code:
1. Asynchronous Long-Polling:
AI generation is not instantaneous; it can take anywhere from 10 seconds to several minutes depending on the complexity of the uploaded PDF files. Instead of blocking the UI thread or forcing the user to manually refresh, this method implements an autonomous "Long-Polling" mechanism. It loops gracefully, yielding the execution thread using `await Future.delayed`, querying the server every 10 seconds without freezing the application.
2. State Mutability:
By altering the `isGenerationCompleted` flag safely within the try-catch block, the Cubit ensures that the Flutter UI is instantly aware when the server transitions from "Generating" to "Complete". This enables the frontend to automatically download the finished Word document the exact second the AI finishes.
